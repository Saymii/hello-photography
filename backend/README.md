# Optional backend (not deployed or connected)

Node 22+ service with Firebase Admin and Google Play Developer API. Install using `npm ci`; run policy tests with `npm test`. `server.js` requires Application Default Credentials with access to the intended Firebase project and Play Developer API. Configure `ANDROID_PACKAGE`, `PLAY_MONTHLY_PRODUCT`, `PLAY_ANNUAL_PRODUCT`, and optional `PORT`. Run behind an HTTPS reverse proxy; listener binds loopback. Do not put ADC files or service-account credentials in Git or the APK.

`POST /v1/purchases/verify` accepts productId and purchaseToken, requires a revocation-checked Firebase ID token, calls Google Play, validates product/account, binds ownership transactionally, acknowledges eligible purchases, and writes server-only entitlements. The future Android purchase launcher must use SHA256(Firebase UID) as obfuscatedAccountId. `GET /v1/entitlement` returns cached access capped by expiry. All verification failures fail closed. The Android client does not call this service yet.

**Production gates:** implement authenticated RTDN Pub/Sub delivery and requery before serving entitlements after refunds/revocation; stored cache alone is insufficient for current refund status. Add integration tests using a separate Firebase/Play test project, concurrency/idempotency tests, secret rotation, monitoring without purchase tokens, abuse limits at ingress, account deletion and an explicit retention policy. Implement purchase launch/restore and backend adapter on Android. Do not enable paid access from this reference service until these gates pass. Policy unit tests are not live Google Play verification.

Admin content: `npm run publish:catalog -- /path/to/catalog.json` uploads unpublished draft documents using a privileged ADC operator. IAM authorizes this CLI; Firestore rules cannot restrict Admin SDK credentials. Grant the operator least privilege and keep it off user devices. Image licensing metadata is required when imageUrl is present. Image upload, complete schema validation, web admin UI, review workflow and client remote catalog consumption remain to implement. Draft `firestore.rules` requires server-assigned admin claims and denies client entitlement writes; it is not deployed.

Licensed photo upload: configure `CONTENT_BUCKET` and run `node upload-image.js /path/photo.webp /path/license.json` with a privileged ADC identity. License JSON must contain `owner`, `source` and `permission` (record explicit redistribution rights). The CLI accepts PNG/JPEG/WebP signatures up to 10 MB, uploads a private draft object, and records SHA256 and license evidence in Firestore. It never makes assets public. Live upload is untested without a bucket/identity and licensed files. `storage.rules` denies client access; a future catalog-delivery service must authorize and serve reviewed free/premium assets. Treat file-signature checks as basic format validation, not malware scanning; use image decoding/re-encoding and moderation in a production ingestion pipeline.
